# 与通用 AI 的能力对照

这份对照不证明 REHEARSE 的模型“比豆包聪明”。飞书官方已经说明，豆包工作可以在用户权限范围内读取企业知识和多份文件、识别异常，并生成文档、表格、网页或轻量应用。把通用 AI 描述成只能聊天，会得到一个虚假的产品优势。

REHEARSE 要证明的是另一件事：活动团队是否值得把一段反复提示、反复校验、反复追问的工作，收敛成一个可复跑产品。

## 选择边界

| 真实任务 | 直接用豆包等通用 AI | 使用 REHEARSE |
| --- | --- | --- |
| 总结一份方案、改写讲稿、生成通知 | 更合适 | 没有必要 |
| 临时分析一份流程表的风险 | 可以完成，前提是用户知道该问什么 | 可直接运行，但优势有限 |
| 两份流程表或 Cue 表对同一环节给出不同版本 | 可以比较，但用户要指定字段并自行保存结果 | 自动定位环节和字段，保留双方文件、行号与原值，并让用户选择本次模拟采用的版本 |
| 多份材料持续更新，需要知道还找谁补什么 | 需要维护提示词、上下文和输出格式 | 按当前环节自动生成材料追问单并保存状态 |
| 讲稿或播放内容与流程时间是否匹配 | 可以按文字量或单份媒体估算 | 同时保留流程预算、文字估算、排练音视频或人工实测、文件指纹、波形分段、下一环节影响和复测 |
| 现场变化会如何影响后续环节 | 需要反复描述时间线、变化位置和计算假设 | 在同一条材料时间线上比较顺延、守时和压缩三种策略，并保留模拟方案与联排结果 |
| 内部材料不能上传到公共云盘 | 取决于企业部署和权限设置 | 当前版本原文件在浏览器本地解析；项目文件由用户自行保存 |

结论：一次性生成与分析优先使用通用 AI。复杂活动在开场前 24—72 小时需要重复检查和闭环时，REHEARSE 才有使用理由。如果团队已经在豆包或飞书内搭建了同等工作流，REHEARSE 可以作为领域规则、测试样本和交互参考，而不是强行替换现有平台。

## 可复验验收用例

以下用例由本地测试和浏览器流程共同验证，不依赖营销表述：

1. 只有流程表、没有讲稿：系统必须指出“讲者／主持／内容负责人”需要补讲稿，并给出“粘贴当前版本”的替代方式；不能因为流程表里出现“演讲稿”三个字就判定已经收到正文。
2. 同一活动包含演讲、直播、产品体验和样品：材料请求必须出现讲稿、技术备援、对外口径和库存；换成纯培训材料后不应照搬样品库存要求。
3. 讲稿文字量接近或超过流程预算：系统必须显示预算、估算或实测用时、剩余量，并写入带讲稿文件名和流程行号的时间风险。
4. 两份材料对同名环节给出不同值：系统必须指出冲突字段、双方文件、行号与原值，且时间线不能重复生成两个同名环节。
5. 完成真人跑稿或导入排练媒体：实测时间必须覆盖文字估算；媒体证据必须保留文件名、指纹和分段；修改讲稿或重新计时后，状态必须重新计算。
6. 注入一个具体变化：三种策略必须给出不同且可解释的时间结果；“守住原时刻”不能把真实重叠悄悄消失。
7. 保存模拟方案后进入联排：口令、开始环节、结束环节和受影响数量必须来自同一次模拟，而不是通用话术。
8. 完成验证：必须记录具体现场结果；记录人和附件可以留空，不额外建立执行人／复核人体系。
9. 导出开场前清单：必须同时包含还需补的材料、内容时长结果、来源证据、模拟方案和验证状态。

- 当前文字估时是提示，不是排期事实；只有讲者真人跑稿才能支持现场时间判断。
- 当前规则评测证明的是已列用例，不代表任意复杂文件都能无人工修正解析。
